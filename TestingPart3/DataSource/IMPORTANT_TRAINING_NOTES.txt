HEAD-ONLY EWASR FINE-TUNING — IMPORTANT NOTES
=============================================

Purpose
-------
This is the first target-domain adaptation baseline. It loads the predefined
non-IMU eWaSR ResNet-18 MLX checkpoint and updates only the existing
decoder.seg_head. It does not replace the three-class head and does not update
the encoder or refinement/fusion modules.

Configuration
-------------
The authoritative experiment configuration is:

  TestingPart3/DataSource/head_only_finetuning_v1.yaml

The YAML contains the paths, split rules, label IDs, model settings,
preprocessing, learning-rate comparison, optimizer, loss, seed, and output
directory. Keep this file with the results so the run can be reproduced.

Data correction made before training
------------------------------------
The requested Tampere masks directory was Tampere_Open-padded-5pct/masks, but
those files are named open_image_001.png through open_image_200.png and were
generated from the open subset. The requested inputs are channel_image files.
Pairing them by numerical position would assign masks to unrelated images and
invalidate training.

The experiment therefore uses the existing matching directory:

  TestingPart3/SAM3_Pseudo_Labels_Generator/
  output/Tampere_Channel_5ppt/masks

Every selected image and mask must have the same filename stem and original
dimensions. The runner validates this before loading MLX.

Splits
------
Training:   channel_image_001 to channel_image_150 (150 image/mask pairs)
Validation: channel_image_151 to channel_image_200 (50 image/mask pairs)
Test:       left_frame_0000, 0030, ..., 1470 (50 image/mask pairs)

The Tampere train/validation split is chronological rather than random, which
prevents adjacent frames from being scattered across both splits. However,
both blocks still belong to the same named Tampere channel sequence, so this
is not as strong as validation on a separate trip. The CataRob test set is a
separate recording.

The CataRob directory contains more frames, but pseudo-label masks currently
exist only for 50 every-30th frames from index 0000 through 1470. Frames after
1470 are not evaluated by this experiment.

Labels and evaluation limitation
--------------------------------
SAM3 masks use raw class IDs:

  0 = obstacle
  1 = water
  2 = sky

The validation and test masks in this first attempt are SAM3 pseudo-labels.
Consequently, IoU and pixel accuracy measure agreement with SAM3, not final
accuracy against independent human annotation. The final thesis claim must be
made using held-out human ground truth. Do not use the test results to choose
the learning rate; learning-rate selection is based only on validation mIoU.

Frozen and trainable components
-------------------------------
Trainable:

  decoder.seg_head only

Frozen:

  ResNet-18 backbone
  MetaFormer attention/refinement blocks
  MetaFormer skip refinement blocks
  SIM1-SIM4 feature-fusion modules
  BatchNorm affine parameters outside the head

Frozen BatchNorm modules remain in evaluation mode. The head BatchNorm affine
weight and bias can train; its running mean and variance are state variables
and do not receive gradients.

Preprocessing
-------------
Images are resized to 512 x 384 and normalised using ImageNet statistics:

  mean = [0.485, 0.456, 0.406]
  std  = [0.229, 0.224, 0.225]

Masks are resized with nearest-neighbour interpolation to 128 x 96, matching
the segmentation-head output. Nearest-neighbour interpolation is mandatory so
the integer class IDs are not blended.

Training settings
-----------------
Optimizer:      AdamW
Learning rates: 3e-4, 1e-3, 3e-3
Primary rate:   1e-3
Weight decay:   1e-4
Batch size:     2
Epochs:         10 per learning-rate trial
Loss:           unweighted three-class cross-entropy
Seed:           4022

Each learning-rate trial starts independently from the same predefined eWaSR
checkpoint. The best epoch for each trial is selected by validation mean IoU.
The best learning rate is selected using validation mean IoU, and only that
selected checkpoint is evaluated on the CataRob test split.

Metrics and outputs
-------------------
The runner records training loss, validation loss, pixel accuracy, mean IoU,
and obstacle/water/sky IoU. It also evaluates the unmodified pretrained model
as a baseline. No inference-runtime benchmarking is part of this experiment.

Outputs are stored below:

  TestingPart3/eWaSR_Head_Fine_Tuning/outputs/
  tampere_channel_head_only_v1/

The generated experiment_summary.txt is the concise performance record. The
selected checkpoint path is recorded in selected_model.json. Do not select a
model by looking at the test results.

First completed run: 2026-09-22
-------------------------------
The learning-rate comparison completed successfully. Validation mean IoU
selected learning rate 1e-3 at epoch 10:

  pretrained validation mean IoU: 0.856286
  selected validation mean IoU:   0.960178

On the separate CataRob test recording, agreement with the SAM3 pseudo-labels
decreased:

  pretrained test mean IoU:       0.902681
  selected test mean IoU:         0.804952
  change:                         -0.097729

  pretrained binary water IoU:    0.907159
  selected binary water IoU:      0.892735
  change:                         -0.014424

  pretrained pixel accuracy:      0.950933
  selected pixel accuracy:        0.921478
  change:                         -0.029455

This is a valid negative result. The head became much better at matching SAM3
on the later Tampere frames but did not transfer that improvement to the
separate CataRob trip. Plausible explanations are over-specialisation to the
single Tampere sequence, camera/domain differences, and SAM3 pseudo-label
differences between datasets. It does not justify claiming that fine-tuning
improved real deployment performance. Independent human-ground-truth testing
is still required.

The detailed result is stored at:

  TestingPart3/eWaSR_Head_Fine_Tuning/outputs/
  tampere_channel_head_only_v1/experiment_summary.txt

Storage note
------------
Each MLX checkpoint contains the full eWaSR parameter set and is about 230 MB.
The first comparison stores best and latest checkpoints for all three learning
rates, so its checkpoint files occupy roughly 1.4 GB. Do not delete them until
the selected model and required audit material have been identified.
